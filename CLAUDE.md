# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project purpose

Agent Bookshelf is a Goodreads-lite **teaching playground** for an AI agents course. Students run it locally and use AI agents to complete homework, so the codebase contains *deliberate gaps*.

## Guardrails

- **Preserve homework gaps unless the task explicitly targets one:**
  - `GET /books/search` (`src/routes/books.ts`) returns a placeholder; `Book.searchBooks()` exists but isn't wired up.
  - No tests for `models/user.ts`, `review.ts`, `shelf.ts`; `tests/models/book.test.ts` and `tests/routes/api.test.ts` are intentionally partial.
  - `src/routes/api.ts` has only minimal presence checks, no real validation.
  - `src/public/css/style.css` is intentionally minimal.
- **Never delete data without asking first.** This covers deleting `bookshelf.db*` files, running `DELETE`/`DROP`/`TRUNCATE` SQL, calling DELETE endpoints against a running app, and removing rows from `seed.sql`. Throwaway test databases under `/tmp` that tests create and clean up are fine.
- **Don't add dependencies, frameworks, or build steps** (ORM, React, Tailwind, bundler, etc.) without asking — the zero-config stack is a design goal.
- **Don't edit `src/db/seed.sql`** unless asked; tests assert on seeded values (book id 1 is "The Pragmatic Programmer", 50 books with "1984" first by title, users Alice/Bob/Carol).
- **Don't edit `dist/`** (generated by `tsc`) and don't commit `bookshelf.db*` (`.gitignore` covers `*.db` but not `-wal`/`-shm`).
- **SQL: always bind values with `?` placeholders.** Never interpolate request data into query strings. The `update*` functions build `SET` clauses from fixed column names only — keep it that way.
- **HTMX fragments:** a fragment's markup must agree with the `hx-target`/`hx-swap` that requests it (`#reviews-list` in `books/show.ejs`, `#shelf-books-list` in `shelves/show.ejs`). Note: both use `hx-swap="outerHTML"` but the fragments don't re-render the element carrying the id, so the id is lost after the first swap. Flag this if you touch that code rather than silently changing behavior.
- **Explain every change in plain language.** After making changes, summarize what changed and why in plain, non-technical terms, for a course student who may not know this stack. Briefly define any technical term you can't avoid.

## Tech stack

- Node ≥ 20, TypeScript ^5.7 (strict, ESM via `"type": "module"`; relative imports use the `.js` suffix, e.g. `'../db/index.js'`)
- Express **^4.21 (v4, not v5)**
- better-sqlite3 ^11.7 — synchronous API, no `await`
- EJS ^3.1 views; HTMX 1.9 (`src/public/htmx.min.js`, 1.9 syntax such as `hx-on::after-request`)
- Vitest ^2.1 + supertest ^7; tsx ^4.19 for dev and the CLI
- Why (see `docs/adr/001-architecture.md`): chosen so students get a zero-config `npx agent-bookshelf` install and agents work with familiar tools — no SPA, no ORM, no frontend build step.

## Commands

```bash
npm install
npm run dev                 # tsx watch src/server.ts → http://localhost:3000 (PORT env overrides)
npm test                    # vitest watch mode
npm run test:run            # vitest single run
npx vitest run tests/models/book.test.ts      # single file
npx vitest run -t "returns a book by id"      # single test by name
npm run build               # tsc → dist/
```

No lint script. `npm start` is likely broken: `tsc` doesn't copy SQL, views, or `public/` into `dist/`. The CLI (`bin/agent-bookshelf.js`) runs `src/server.ts` via `npx tsx`, so `src/` is the real runtime.

## Architecture

- **DB (`src/db/index.ts`):** `initDb(path?)` opens a module-level singleton (default `./bookshelf.db` in the cwd), enables WAL + foreign keys, runs `schema.sql` (idempotent), and runs `seed.sql` only when `users` is empty. `getDb()` throws before `initDb()`. Deleting `bookshelf.db*` resets data (ask first).
- **Models (`src/models/*.ts`):** plain exported functions taking `db: Database.Database` first, using prepared statements. Joined read shapes get their own interface (e.g. `ReviewWithDetails`).
- **Routes:** each handler calls `getDb()` and passes it to model functions.
  - `books.ts` (`/`), `shelves.ts` (`/shelves`), `reviews.ts` (`/reviews`) render EJS pages; their POST/DELETE handlers return HTML fragments (`books/reviews-list`, `shelves/books-list`) for HTMX.
  - `api.ts` (`/api`) is the JSON surface for books, users, reviews, and shelves.
- **`src/server.ts`** default-exports `app` and only auto-starts when run as the main module, so tests drive `app` with supertest without binding a port.
- **Schema constraints:** unique `books.isbn`; one review per `(user_id, book_id)`, rating 1–5; unique shelf `(user_id, name)`; `shelf_books` join table; FKs cascade on delete.

## Testing conventions

- Files match `tests/**/*.test.ts`; Vitest `globals: true`. `tests/setup.ts` is **not** registered in `vitest.config.ts`, so each file does its own setup.
- `beforeEach`: `initDb('/tmp/<unique-name>.db')` for a fresh seeded DB; `afterEach`: `closeDb()` and delete the file. Use a distinct path per test file.
- Route tests: `request(app)` (supertest) against the default export of `src/server.ts`.

## Capstone kit: backlog refinement

This repo also contains a Claude Code kit that turns raw GitHub issues (label `raw`) into feature specs.

- Entry point: `prompts/brief.md` — run it with `Run prompts/brief.md for issue #<NUMBER>`
- Spec format: `specs/TEMPLATE.md` (5 required sections). Quality example: `specs/manual-baseline.md`
- Skills: `spec-writer` (writes the spec), `business-lens` (build now / later / not at all)
- Subagent: `spec-critic` (read-only reviewer)
- Hook: `.claude/hooks/check-spec.js` blocks a spec missing a required section, and blocks access to `.env` and credential files
- Memory: `decisions.md` — read it before every spec; apply its "Rules learned"
- GitHub access is READ-ONLY through the `github` MCP server. Never create, edit, comment on or close issues.
- Specs are drafts. The product owner reviews every spec before it goes anywhere.
